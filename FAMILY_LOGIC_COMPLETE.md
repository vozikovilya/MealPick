# 📋 Полная логика блока "Семья"

## 🎯 Назначение блока

Блок "Семья" предназначен для объединения пользователей в группы для совместного выбора блюд. Это позволяет:
- Делиться рецептами с близкими
- Совместно планировать меню
- Координировать покупки продуктов
- Голосовать за блюда

---

## 👥 Роли в семье

### 1. Глава семьи (Owner)
**Права:**
- ✅ Создал семью
- ✅ Может удалить семью
- ✅ Может принимать/отклонять заявки на вступление
- ✅ Может удалять участников из семьи
- ✅ Может назначать роль "Поварушка"
- ✅ Может удалять ЛЮБЫЕ блюда в меню семьи
- ✅ Видит все заявки на вступление
- ✅ Может редактировать профиль семьи

**Отображение:**
- Бейдж "👑 Глава семьи" (жёлтый)
- Всегда первый в списке участников

---

### 2. Поварушка (Chef)
**Права:**
- ✅ Может удалять ЛЮБЫЕ блюда в меню семьи (как и глава)
- ✅ Может создавать блюда
- ✅ Может отправлять запросы на выбор блюд
- ❌ НЕ может удалять семью
- ❌ НЕ может принимать заявки
- ❌ НЕ может удалять участников
- ❌ НЕ может назначать роли

**Отображение:**
- Бейдж "👨‍🍳 Поварушка" (синий)
- Второй в списке участников (после главы)

**Назначение:**
- Только глава семьи может назначить эту роль
- Можно снять роль (вернуть в обычного участника)

---

### 3. Обычный участник (Member)
**Права:**
- ✅ Может создавать свои блюда
- ✅ Может удалять ТОЛЬКО свои блюда
- ✅ Может отправлять запросы на выбор блюд
- ✅ Может видеть все блюда семьи
- ❌ НЕ может удалять чужие блюда
- ❌ НЕ может управлять семьёй

**Отображение:**
- Без бейджа роли
- В списке по дате присоединения

---

## 🔄 Взаимодействие между пользователями

### Сценарий 1: Создание семьи

**Действия:**
1. Пользователь нажимает "Профиль" → "Профиль семьи"
2. Видит форму создания семьи
3. Заполняет:
   - Название семьи (обязательно)
   - Аватар семьи (эмодзи)
   - Описание (опционально)
4. Нажимает "Создать профиль семьи"
5. Появляется модальное окно со ссылкой-приглашением
6. Может скопировать ссылку или поделиться в соцсетях

**Результат:**
- Пользователь становится главой семьи
- Генерируется уникальная ссылка-приглашение
- Создаётся запись в БД

---

### Сценарий 2: Присоединение к семье

**Действия:**
1. Пользователь получает ссылку-приглашение
2. Нажимает "Профиль" → "Профиль семьи"
3. Видит форму "Присоединиться к семье"
4. Вставляет ссылку
5. Нажимает "Отправить заявку"
6. Отправляется заявка главе семьи

**Результат:**
- Заявка сохраняется в БД со статусом "pending"
- Глава семьи получает уведомление
- Пользователь видит сообщение "Заявка отправлена"

---

### Сценарий 3: Рассмотрение заявки (глава семьи)

**Действия:**
1. Глава семьи видит уведомление о заявке
2. Переходит в "Профиль семьи"
3. Видит секцию "Заявки на вступление"
4. Нажимает "Рассмотреть" на заявке
5. Открывается модальное окно с информацией о заявителе
6. Выбирает:
   - **Принять** → пользователь добавляется в семью
   - **Отклонить** → заявка отклоняется
   - **Позже** → закрывает модальное окно

**Результат при принятии:**
- Пользователь добавляется в семью с ролью "member"
- Отправляется уведомление пользователю
- Появляется модальное окно "Добро пожаловать в семью!"

**Результат при отклонении:**
- Заявка помечается как "rejected"
- Отправляется уведомление пользователю
- Появляется модальное окно "Заявка отклонена"

---

### Сценарий 4: Назначение роли "Поварушка"

**Действия:**
1. Глава семьи переходит в "Профиль семьи"
2. Видит список участников
3. Находит нужного участника
4. Нажимает кнопку "Действия ▼"
5. Выбирает "Назначить Поварушкой"
6. Роль назначается

**Результат:**
- Участник получает роль "chef"
- Появляется бейдж "👨‍🍳 Поварушка"
- Получает право удалять любые блюда

**Снятие роли:**
1. Глава семьи нажимает "Действия ▼"
2. Выбирает "Убрать роль Поварушки"
3. Роль снимается, участник становится обычным

---

### Сценарий 5: Удаление участника из семьи

**Действия:**
1. Глава семьи переходит в "Профиль семьи"
2. Находит участника
3. Нажимает "Действия ▼"
4. Выбирает "Удалить из семьи"
5. Появляется модальное окно подтверждения
6. Подтверждает удаление

**Результат:**
- Участник удаляется из семьи
- Его блюда остаются в меню (но он больше не видит новые блюда семьи)
- Отправляется уведомление (опционально)

---

### Сценарий 6: Удаление блюда

**Права на удаление:**

| Кто удаляет | Свои блюда | Чужие блюда |
|-------------|------------|-------------|
| Владелец блюда | ✅ Да | - |
| Глава семьи | ✅ Да | ✅ Да |
| Поварушка | ✅ Да | ✅ Да |
| Обычный участник | ✅ Да | ❌ Нет |

**Логика проверки прав (backend):**
```php
// Владелец блюда может удалить
if ($recipe['user_id'] == $userId) {
    $canDelete = true;
} else {
    // Глава семьи или поварушка могут удалить
    $stmt = $db->prepare("
        SELECT f.owner_id, fm.role
        FROM families f
        JOIN family_members fm ON f.id = fm.family_id
        WHERE fm.user_id = ? AND fm.status = 'accepted'
    ");
    $stmt->execute([$userId]);
    $family = $stmt->fetch();
    
    if ($family) {
        if ($family['owner_id'] == $userId || $family['role'] === 'chef') {
            $canDelete = true;
        }
    }
}
```

### Сценарий 7: Отправка запроса на выбор блюд

**Действия:**
1. Пользователь нажимает "Спросить"
2. Выбирает блюда из своего меню
3. Выбирает получателя:
   - Всей семье
   - Конкретному участнику
4. Добавляет милое сообщение (опционально)
5. Нажимает "Отправить запрос"

**Результат:**
- Создаётся запрос в БД
- Получатель получает уведомление
- Появляется модальное окно "Запрос отправлен!"

---

### Сценарий 8: Ответ на запрос (свайпы)

**Действия:**
1. Получатель видит уведомление
2. Нажимает "Выбрать блюда"
3. Открывается экран свайпов
4. Свайпает карточки блюд:
   - Вправо → "Хочу"
   - Влево → "Не хочу"
5. После всех свайпов видит резюме
6. Нажимает "Отправить выбор"

**Результат:**
- Отправитель получает уведомление
- Может посмотреть выбранные блюда

---

### Сценарий 9: Удаление семьи

**Действия:**
1. Глава семьи переходит в "Профиль семьи"
2. Прокручивает вниз
3. Нажимает "Удалить профиль семьи"
4. Появляется модальное окно подтверждения
5. Подтверждает удаление

**Результат:**
- Семья удаляется из БД
- Все участники теряют доступ к семье
- Блюда остаются у своих владельцев
- Отправляются уведомления участникам (опционально)

**Важно:**
- Только глава семьи может удалить семью
- Обычные участники НЕ видят кнопку удаления

---

### Сценарий 10: Шаринг ссылки-приглашения

**Действия:**
1. Глава семьи переходит в "Профиль семьи"
2. Находит секцию "Ссылка для приглашения"
3. Нажимает "📤 Поделиться в соцсетях"
4. Открывается модальное окно с выбором соцсети:
   - Telegram
   - WhatsApp
   - Viber
   - ВКонтакте
   - Facebook
   - Twitter
5. Выбирает соцсеть
6. Открывается новая вкладка с предзаполненным сообщением

**Результат:**
- Ссылка-приглашение отправляется через выбранную соцсеть
- Получатель может перейти по ссылке и отправить заявку

## 🗄️ Структура базы данных

### Таблица `families`
```sql
CREATE TABLE families (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    avatar VARCHAR(10) DEFAULT '👨‍👩‍👧‍👦',
    description TEXT,
    owner_id INT NOT NULL,
    invite_link VARCHAR(255) UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (owner_id) REFERENCES users(id) ON DELETE CASCADE
);
```

### Таблица `family_members`
```sql
CREATE TABLE family_members (
    id INT AUTO_INCREMENT PRIMARY KEY,
    family_id INT NOT NULL,
    user_id INT NOT NULL,
    role ENUM('owner', 'chef', 'member') DEFAULT 'member',
    status ENUM('pending', 'accepted', 'rejected') DEFAULT 'accepted',
    joined_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (family_id) REFERENCES families(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    UNIQUE KEY unique_membership (family_id, user_id)
);
```

### Таблица `family_join_requests`
```sql
CREATE TABLE family_join_requests (
    id INT AUTO_INCREMENT PRIMARY KEY,
    family_id INT NOT NULL,
    user_id INT NOT NULL,
    status ENUM('pending', 'accepted', 'rejected') DEFAULT 'pending',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    processed_at TIMESTAMP NULL,
    FOREIGN KEY (family_id) REFERENCES families(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

### Таблица `family_statuses`
```sql
CREATE TABLE family_statuses (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    family_id INT NOT NULL,
    title VARCHAR(50) NOT NULL,
    emoji VARCHAR(10) NOT NULL,
    created_by INT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (family_id) REFERENCES families(id) ON DELETE CASCADE,
    FOREIGN KEY (created_by) REFERENCES users(id) ON DELETE CASCADE
);
```

## 🔌 API Endpoints

### Создание и управление семьёй
- `POST /api/family/create.php` - Создание семьи
- `GET /api/family/get.php` - Получение информации о семье
- `DELETE /api/family/delete.php` - Удаление семьи

### Присоединение к семье
- `POST /api/family/join.php` - Отправка заявки на вступление
- `POST /api/family/respond-request.php` - Обработка заявки (принять/отклонить)

### Управление участниками
- `DELETE /api/family/remove-member.php` - Удаление участника
- `POST /api/family/assign-role.php` - Назначение роли

### Статусы
- `POST /api/family/add-status.php` - Добавление статуса
- `DELETE /api/family/remove-status.php` - Удаление статуса
