# 📋 Полная логика блока "Спросить"

## 🎯 Назначение блока

Блок "Спросить" предназначен для отправки запросов другим участникам семьи с предложением выбрать блюда из меню. Это позволяет:
- Узнать, что хочет приготовить другой участник
- Совместно планировать меню
- Голосовать за блюда
- Заказывать доставку

---

## 🔄 Полный цикл взаимодействия

### Сценарий 1: Отправка запроса всей семье

**Шаг 1: Отправитель**
1. Нажимает "Спросить" в нижнем меню
2. Выбирает "Всей семье"
3. Выбирает режим отправки:
   - **Категории** - выбирает одну или несколько категорий (Завтрак, Обед, Ужин)
   - **Блюда** - выбирает конкретные блюда из своего меню
   - **Доставка** - выбирает варианты доставки
4. Добавляет милое сообщение (опционально)
5. Нажимает "Отправить запрос"

**Шаг 2: Система**
- Создаёт запрос в БД с параметрами:
  - `from_user_id` - ID отправителя
  - `to_family_id` - ID семьи (если отправлено всей семье)
  - `recipe_ids` - список ID блюд (JSON)
  - `mode` - режим отправки (category/select/delivery)
  - `category` - категория (если mode=category)
  - `message` - милое сообщение
  - `delivery_ids` - список ID доставок (если mode=delivery)
  - `status` - "pending"

**Шаг 3: Получатели (все участники семьи)**
- Каждый участник семьи получает уведомление:
  ```
  🍳 [Имя отправителя] хочет, чтобы вы выбрали блюда!
  💌 "Что будем кушать?"
  ```
- Уведомление появляется:
  - В списке уведомлений (вкладка "Запросы")
  - Как модальное окно (если это первое уведомление)

**Шаг 4: Получатель выбирает блюда**
1. Нажимает "Выбрать блюда" в уведомлении
2. Открывается экран свайпов
3. Свайпает карточки блюд:
   - **Вправо** → "Хочу" (добавляется в список выбранных)
   - **Влево** → "Не хочу" (пропускается)
4. После всех свайпов видит резюме:
   - Список выбранных блюд
   - Список пропущенных блюд
5. Нажимает "Отправить выбор"

**Шаг 5: Система**
- Обновляет запрос в БД:
  - `status` → "completed"
  - `responses` → JSON с ответами всех участников
- Создаёт уведомление для отправителя:
  ```
  ✅ [Имя получателя] выбрал(а) X блюд для вас! 🎉
  ```

**Шаг 6: Отправитель видит результат**
1. Получает уведомление
2. Нажимает "Посмотреть выбор"
3. Видит экран с результатами:
   - Список выбранных блюд
   - Список пропущенных блюд
   - Информация о том, кто что выбрал

---

### Сценарий 2: Отправка запроса конкретному участнику

**Отличия от сценария 1:**
- В шаге 1 отправитель выбирает "Конкретному участнику"
- Выбирает конкретного участника из списка
- В шаге 3 уведомление получает только выбранный участник
- В шаге 5 только этот участник может ответить

---

### Сценарий 3: Режим "Категории"

**Как работает:**
1. Отправитель выбирает одну или несколько категорий:
   - 🌅 Завтрак
   - ☀️ Обед
   - 🌙 Ужин
2. Система собирает все блюда из выбранных категорий из меню отправителя
3. Эти блюда отправляются получателю на выбор

**Пример:**
- Отправитель выбирает "Завтрак" и "Обед"
- В его меню есть:
  - Завтрак: Овсянка, Блинчики, Сырники
  - Обед: Паста, Суп, Салат
- Получателю отправляются все 6 блюд

---

### Сценарий 4: Режим "Блюда"

**Как работает:**
1. Отправитель видит все блюда из своего меню, сгруппированные по категориям
2. Выбирает конкретные блюда (можно из разных категорий)
3. Эти блюда отправляются получателю на выбор

**Пример:**
- Отправитель выбирает:
  - Овсянка (Завтрак)
  - Паста (Обед)
  - Тирамису (Десерт)
- Получателю отправляются только эти 3 блюда

---

### Сценарий 5: Режим "Доставка"

**Как работает:**
1. Отправитель выбирает варианты доставки:
  - 🍣 Суши
  - 🍕 Пицца
  - 🍔 Бургеры
  - 🍜 Вок
  - 🌯 Шаурма
  - 🥗 Салаты
2. Эти варианты отправляются получателю на выбор
3. Получатель свайпает не блюда, а варианты доставки

**Пример:**
- Отправитель выбирает: Суши, Пицца, Вок
- Получатель свайпает эти 3 варианта
- Выбирает, например, "Пицца"
- Отправитель видит результат

## 🗄️ Структура базы данных

### Таблица `swipe_requests`
```sql
CREATE TABLE swipe_requests (
    id INT AUTO_INCREMENT PRIMARY KEY,
    from_user_id INT NOT NULL,
    to_user_id INT,
    to_family_id INT,
    recipe_ids JSON NOT NULL,
    status ENUM('pending', 'completed') DEFAULT 'pending',
    mode ENUM('category', 'select', 'delivery'),
    category VARCHAR(50),
    message TEXT,
    delivery_ids JSON,
    responses JSON,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (from_user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (to_user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (to_family_id) REFERENCES families(id) ON DELETE CASCADE
);
```

**Поля:**
- `from_user_id` - ID отправителя
- `to_user_id` - ID получателя (NULL если отправлено всей семье)
- `to_family_id` - ID семьи (NULL если отправлено конкретному пользователю)
- `recipe_ids` - JSON массив ID блюд (или ID доставок для mode=delivery)
- `status` - статус запроса (pending/completed)
- `mode` - режим отправки (category/select/delivery)
- `category` - категория (если mode=category)
- `message` - милое сообщение
- `delivery_ids` - JSON массив ID доставок (если mode=delivery)
- `responses` - JSON объект с ответами участников

**Пример `responses`:**
```json
{
  "1": [1, 3, 5],      // Пользователь 1 выбрал блюда с ID 1, 3, 5
  "2": [2, 4]          // Пользователь 2 выбрал блюда с ID 2, 4
}
```

```

```

**Параметры:**
```json
{
  "recipe_ids": [1, 2, 3],
  "to_user_id": 2,
  "to_family_id": 1,
  "mode": "select",
  "category": "breakfast",
  "message": "Что будем кушать?",
  "delivery_ids": [1, 2]
}
```

**Ответ:**
```json
{
  "success": true,
  "message": "Запрос отправлен",

    "requestId": 123

}
```
